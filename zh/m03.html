拒绝重定向

  • 仅本地请求带着 RejectRedirects 运行
  • 否则你的会议文本会被悄悄转发

来源ListenToMe/Sources/ListenToMeCore/OllamaProvider.swift:138-142, 208-214

大多数 HTTP 栈默认会静默地跟随重定向。 这在这里很要紧，因为即使一个通过了本地元数据检查的服务器，也可能用一个指向任意地址的重定向来回应你的聊天请求，而 HTTP 栈会热心地把你的会议文本一并转发过去。 ListenToMe 选择拒绝，拒绝的代码就在幻灯片上：一个小小的委托类 RejectRedirects，它的重定向处理方法对每一个重定向都回答 nil，于是请求终止，而不是跟随。 类名就是策略：重定向不是一个可以靠配置规避的边缘情况，而是一条你的会议文本绝不能经过的通道。

  • 页面上ListenToMe/Sources/ListenToMeCore/OllamaProvider.swift:138-142在 a9bde8e 打开

在大多数 HTTP 栈中，跟随重定向默认是静默的。即使一个通过了本地校验的服务器，也可能对 /api/chat 返回一个指向任意地址的 3xx，而 HTTP 栈会「热心地」把你的会议文本转发过去。这个委托选择拒绝：遇到任何 HTTP 重定向，它都回答 nil，请求随之终止。注释说明了原因：在仅本地模式下，绝不带着会议文本跟随重定向。没有这道防线，元数据检查就会在传输层被绕过。时间：两分钟。过渡：失败即关闭的默认值。
