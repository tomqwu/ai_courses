基础#BCGMRSWY

基础词汇

写给从没编程过的人：构建软件时最常见的词，用大白话解释。

Git（版本控制工具）
一个记录项目文件每个版本的工具，让你能看到改了什么，并随时回到以前的版本。 就像共享文档里的版本历史，只不过针对的是整个文件夹。
仓库（repository）
由 Git 跟踪的项目文件夹：所有文件，加上每一次改动的完整历史。 一个自带无限撤销历史的项目文件夹。
提交（commit）
项目在某一刻的快照，附一句说明改了什么。 按下“保存”并在这次保存上贴个标签，以后能找到它。
分支（branch）
仓库里一条独立的工作线，让你尝试改动而不影响主版本。 一份可以随意修改的草稿副本，改好后再合并回原稿。
主分支（main）
保存项目正式、最新版本的那个分支。 大家都认可的那份正本。
拉取请求（pull request，PR）
请求把一个分支的改动并入另一个分支，别人可以先审阅。 交上一份改过的稿子并附言：“这是我改的地方——请先检查再放进去。”
合并（merge）
把一个分支的改动并入另一个分支。 把改好的草稿并回正本。
克隆（clone）
把一个仓库连同历史完整地下载到你的电脑上。 给共享的项目文件夹做一份属于你自己的完整副本。
推送（push）
把你电脑上的新提交发送到线上的共享副本（例如 GitHub）。 把你保存的改动上传，让其他人都能看到。
GitHub（代码托管平台）
一个把 Git 仓库存放在网上的网站，方便大家共享、审阅和发布。 项目文件夹的线上之家，就像专为代码打造的共享网盘。
GitHub Pages（静态网站托管）
GitHub 的免费服务，把仓库里的文件变成一个公开网站。 一个免费的橱窗，展示一文件夹的网页。
终端（terminal）
一个输入命令、而不是点击来操作电脑的窗口。 用打字给电脑发指令，而不是去点按钮。
命令（command）
在终端里输入的一条指令，例如 `git status`。 对电脑说的一句指令。
命令行工具（CLI）
在终端里通过输入命令来使用的程序（命令行界面）。 一个没有按钮的应用——你通过打字和它说话。
文件夹与路径（folder / path）
文件夹（也叫目录）装着文件；路径是它的地址，比如 `code/my-site/index.html`。 文件夹是抽屉，路径是去那个抽屉的路线。
README（说明文件）
仓库的首页文件，说明这个项目是什么、怎么用。 包装盒里的说明书。
Markdown（轻量标记语言）
在纯文本文件里写带格式文字的简单方法：`#` 表示标题，`**粗体**` 表示粗体。 打字时用的速记符号，会变成整齐的排版。
HTML 与 CSS（网页结构与样式）
HTML 是网页的文字和结构；CSS 决定它的样子（颜色、字体、布局）。 HTML 是房间里的文字和家具，CSS 是油漆和装饰。
静态网站（static website）
只由文件（网页、图片）组成的网站，原样发给浏览器，背后没有服务器程序。 一本印好的宣传册：每个人拿到的都是同样的页面。
网址（URL）
一个网络地址，例如 https://example.com/page。 网页在互联网上的门牌地址。
服务器（server）
一个等待请求（来自浏览器或应用）并作出回应的程序。 餐厅的后厨：点单进来，菜品出去。
客户端（client）
人们直接使用的部分——浏览器或应用——它向服务器发出请求。 点单的食客。
接口（API）
一个程序向另一个程序请求东西的约定方式：它接受哪些请求、返回什么。 餐厅的菜单：你能点什么、会拿到什么。
端点（endpoint）
服务器上处理某一类请求的具体地址，比如 `/api/login`。 服务台的某个窗口——这个办票，那个退款。
数据库（database）
应用存放信息（用户、订单、排班）的地方，重启后也不会丢。 一张超大、超快、由应用读写的表格。
查询（query）
向数据库提出的问题，比如“给我这个组织的活动”。 在那张表格里做一次搜索。
SaaS（软件即服务）
软件即服务：人们在浏览器里使用、按订阅付费、由开发者在自己的服务器上运行的应用。 在线租用一件工具，而不是买一盒软件。
多租户（multi-tenant）
一个应用、一个数据库同时服务许多互相独立的客户，每个客户只能看到自己的数据。 一栋公寓楼：楼是共用的，每户是私密的。
登录与令牌（login / token）
登录证明你是谁；随后应用给你的浏览器一个令牌——每次请求都出示的一张签名通行证。 在门口出示证件，然后整晚戴着腕带。
本机地址（localhost）
你的电脑用来指代自己的地址：运行在 localhost 的程序就在你自己的机器上，而不在互联网上。 拨打你自己的电话号码。
部署（deploy）
把应用或网站的新版本放到用户能访问的地方。 把新货摆上货架，打开店门。
托管（hosting）
互联网上一台让你的网站或应用持续运行、供别人访问的电脑。 给你的网站租一个店面。
安装与包管理器（package manager）
安装是把程序放到你的电脑上；包管理器用一条命令替你安装和更新程序。依赖是一个项目需要的其他程序。 一个用打字操作的应用商店；依赖就是一道菜谱需要的食材。
Python 与 Swift（编程语言）
编程语言：Python 常用于脚本、工具和服务器；Swift 用于苹果应用（iPhone、Mac）。 两种可以用来给电脑下指令的不同语言。
JSON（数据格式）
一种常见的文本数据格式，用花括号写名字和值，比如 {"name": "Maria"}。 一张带标签格子的整齐表单，程序能读懂。
配置（configuration）
存放在文件里的设置，不改代码就能改变程序的行为。 把应用的设置页写进一个文件里。
代码与源码（source code）
组成程序的书面指令；代码库就是一个项目的全部代码。 程序照着烹饪的那本菜谱。
缺陷（bug）
程序里导致它行为出错的错误。 菜谱里一个会毁掉整道菜的笔误。
测试（test）
检查另一个程序是否仍按预期工作的小程序；测试套件就是所有测试的集合。 每次你改动东西时，机器人都会跑一遍的检查清单。
持续集成（CI）
每当有人推送改动时，自动运行项目测试的服务。 在门口检查每一批送货的质检员。
测试覆盖率（test coverage）
程序中真正被测试运行到的代码行所占的比例。 检查员实际走过了这栋房子的多少地方。
AI 模型（model）
读取文字并写出回复的、训练好的 AI；LLM（大语言模型）就是聊天助手背后的那一类。 聊天助手里的那颗大脑。
AI 助手（agent）
一个能在你的电脑上干活的 AI 助手——读文件、运行命令、写代码——你只需用普通话语提出要求。 一个能干的帮手，照你写下的指示做事，并给你看它做了什么。
提示词（prompt）
你给 AI 模型或助手的话，告诉它你想要什么。 你写在点单纸上的那句要求。
Ollama（本地模型运行工具）
一个免费程序，在你自己的电脑上运行 AI 模型，而不是在云端。 住在你笔记本电脑里的小型 AI 引擎。
云端（cloud）
由公司在互联网上运营、替你做事或存数据的电脑。 你租用的别人的电脑。
端侧（on-device）
在你自己的手机或电脑上完成，数据不会离开设备。 在家做饭，而不是把食材送出去。
隐私模式（privacy mode）
决定你的数据可以去哪里的设置——哪儿都不去、只在本机，或去云服务。 一个决定谁能进房间的开关。
macOS、iOS 与 Xcode
macOS 运行在 Mac 上，iOS 运行在 iPhone 上；Xcode 是苹果免费提供的、为两者开发应用的软件。 苹果设备的操作系统，以及制作它们应用的工坊。
模拟器（Simulator）
Mac 屏幕上的一部虚拟 iPhone，不用真手机就能试用应用。 就像飞行模拟器，只不过模拟的是你的应用。
发布版本（release）
应用的一个完成版本，带编号（比如 1.4.4），供人下载。 一本书的新版上架销售。
规格（spec）
一份写清楚某个功能必须做什么的说明，清楚到别人也能照着做出来。 动工之前建筑师写好的设计要求。
哈希（hash / checksum）
根据文件内容算出的一串短码；哪怕改动一个字节，这串码也会变。 文件的指纹。
流水线（pipeline）
一串步骤，每一步接收上一步的输出，例如 音频 → 文字 → 回答。 一条装配线。
流式传输（streaming）
边生成边一点点发送回复，而不是最后一次性发出。 边下载边看视频。
落地页与行动号召（CTA）
一个介绍某项产品、并请读者做一件事的网页——这件事就是行动号召（CTA），比如“购买”。 一个只挂着一块醒目招牌的橱窗：“请进”。
漏斗（funnel）
从第一次听说一个产品到购买它的各个步骤；每一步都会少一些人。 厨房的漏斗：上面宽，下面窄。

:cloud 别名（:cloud alias） M0 M2
一个由*本地*守护进程从远端后端提供服务的模型。它的名字以 :cloud 或 -cloud 结尾，或者 /api/tags 报告了 remote_host/remote_model。ListenToMe/Sources/ListenToMeCore/ModelRanking.swift:66-72；course/03-content/m02-ondevice-app/tinycopilot/src/tinycopilot/model_router.py。
[P] 与 [US#] 标记（[P] vs. [US#]） M4
[P] 标记一个可以与相邻任务并行的任务（不同文件，没有依赖）；[US#] 把任务绑定到它所服务的用户故事。两者是正交的，不是同义词。
[待澄清] 标记（[NEEDS CLARIFICATION]） M4
模板中表示未决决策的标记；关卡要求在规划之前一个都不剩。— SignUpFlow/.specify/templates/spec-template.md。
“测试通过”与证据（"Tests passed" vs. evidence） M1
没有命令、日期、环境和版本的计数只是一个说法；证据是可审计的。
一次性定价（One-time pricing） M7
因为每用户边际成本不重复发生而只收一次费用——这是端侧产品的规律。例证：MacWhisper 那一行，ListenToMe/docs/competition-analysis.md。
上下文窗口（Context window (recentContext)） M2
按字符预算截取、发送给提示词的那一段转写文本。从最新的开始往回装，默认 4,000 个字符，永不为空。ListenToMe/Sources/ListenToMeCore/ConversationStore.swift:76-87。
不可变发布（Immutable release） M6
已发布的版次从不覆盖；需要时另发一个新的。 出处：ai_qe/CONTRIBUTING.md 和 ai_qe/releases.md。
中断演练（Disruption drill） M5
一个故意打破正常路径、并规定拒绝应当是什么样子的场景，例如 CH-04 中两位敬拜带领都不可用、发布被拒绝。（SignUpFlow/docs/playbooks/church.md:73）
临时结果与最终结果（Partial vs. final） M2 M2
进行中的实时文本，与已定稿的语句。临时结果从不进入已定稿日志；id 相同的最终结果会取代它的临时结果。course/03-content/m02-ondevice-app/tinycopilot/src/tinycopilot/conversation_store.py。
主动触发关卡（Proactive gate） M2
主动回答触发之前的四个条件。已定稿、来自 .others、通过问题检测、在防抖窗口之外。ListenToMe/Sources/ListenToMeCore/ContextEngine.swift:41-50。
主动选择云端与默认云端（Cloud opted-in vs. cloud by default） M3
主动选择是用户做出并看得见的模式选择。默认走云端按原则不在范围内（ListenToMe/CLAUDE.md）。
主张层级（Claim level） M6
每个数字都必须带的四种标签之一：任务级效率、释放的 QA 产能、硬性节省、 软件总支出影响。出处：ai_qe/docs/principles.md；在 evidence-dataset.md 中有转载。
主目录（Home folder） M9
终端打开时所在的文件夹，在两个系统上都写作 ~：Windows 上是 C:\Users\ada，Mac 上是 /Users/ada。出处：lesson.md，M9.2 分段。
云端别名（Cloud alias） M3
一个以 :cloud 结尾的模型名（或者一个名字听起来像本地、实际由远端支撑的模型），它在本地守护进程上安装并列出，推理却在远程运行 —— ListenToMe/docs/manual-smoke-test.md；ListenToMe/Sources/ListenToMeCore/ModelPrivacy.swift:16。
产品原型（Archetype） M0
本课程构建的三种产品形态之一：端侧应用、规格驱动的 SaaS、 专业知识产品。它们的区别在于技术重心，而不在方法。 — course/03-content/m00-orientation/lesson.md
人工冒烟测试（Manual smoke test） M3
覆盖麦克风采集、系统音频和实时语音转文字的层级，这些都需要一个 GUI 会话和手动授权——一份编号的、可重复的脚本 —— ListenToMe/docs/manual-smoke-test.md:1-7。
人设指令（Persona directive） M2
附加到每个角色系统提示词后面的预设指导。手动面板和自动评审走同一条代码路径。ListenToMe/Sources/ListenToMeCore/Prompt.swift:245-260。
仅限邀请的增长（Invitation-only growth） M5
注册以原子方式创建一个组织及其第一位管理员，且从不加入已有组织；后续账号通过管理员创建的一次性邀请加入。（SignUpFlow/AGENTS.md:59；docs/playbooks/coverage.json 中的 BO-02）
从分支部署（Deploy from a branch） M9
最简单的 GitHub Pages 模式：按原样发布某一个分支和文件夹里的文件。在 Settings → Pages 下设置。出处：lesson.md，M9.3 分段。
从规格到交付的循环（Spec-to-Ship Loop） M0 M8
每个模块都使用的六阶段方法：研究 → 规格 → 构建 → 验证 → 发布 → 证明，每个阶段都有一件真实的产物。 — course/00-research/00-synthesis.md
仓库（Repository） M9
一个由 Git 记录其历史的文件夹，加上它在 GitHub 上的副本。在终端里用 gh repo create 创建。出处：lab.md，第 4 步。
代码托管平台（GitHub） M9
保存仓库副本并能把它们发布出去的网站。它和 Git 不是一回事：Git 运行在你的电脑上，GitHub 运行在互联网上。出处：lesson.md，M9.1 分段。
价值锚点（Value anchor） M7
你的产品所替代的东西——工时、人员或某个工具订阅——表示为一个可比较的金额。出处：lab.md 第 2 步。
价格与成本底线（Price vs. cost floor） M7
价格是你的要价；底线是它下面的保本算术。低于底线的价格就是补贴，无论对标区间怎么说。
任务文件（tasks.md） M4
第 2 阶段的产出：[ID] [P?] [US#] 格式的勾选任务，测试先行，精确的文件路径，每个故事一个检查点。— SignUpFlow/specs/000-user-onboarding/tasks.md。
任务行（Task line） M1
tasks.md 中一条可执行的条目，采用 [ID] [P?] [Story] 格式，带精确的文件路径，并且先写测试。真实的例子："T027 [US1] Implement POST /api/sms/send endpoint per contracts/sms-api.md in api/routers/sms.py"。（SignUpFlow/specs/019-sms-notifications/tasks.md）
优雅降级（Graceful degradation） M3
关闭 AI 后，采集、转写和保存照常工作；app 是降级，而不是停止 —— ListenToMe/README.md，“AI processing mode”。
依赖锁差异检查（Dependency-lock diff） M3
当签入的依赖锁文件与生成的工作区的已解析锁文件出现偏差时，让构建失败的 CI 步骤 —— ListenToMe/.github/workflows/ci.yml:24, 35。
信任边界（Trust boundary） M3
一项保证的诚实边界。仅本地模式信任已安装的本地 Ollama 服务及其元数据；它校验的是一份自我描述，而不是守护进程本身 —— ListenToMe/README.md，“Privacy”。
做什么与怎么做（WHAT vs. HOW） M4
做什么是用户可见的行为，属于 spec.md；怎么做是技术栈、版本和存储，属于 plan.md。关卡的第一条规则会让提到某项技术的规格不通过。
健康分与独立判定（Health score vs. oracle） M5
健康分是求解器给自己打分（有任何硬约束违规即为 0，否则为 100 − soft/10）；判定器则从排班表重新计算正确性。
健康分（Health score） M0
求解器为生成的排班表打出的 0–100 质量指标，由 api.cli.main solve 打印（SignUpFlow/api/cli/main.py:193）。它的值取决于版本：在 2026-09-16 的 head 上，示例工作区打印 0.0/100，有两个硬约束违规。 — SignUpFlow/README.md
充分证据（Sufficient evidence） M6
置信区间不跨越相关决策边界的结果。单独的点估计永远不够充分； 出处：ai_qe/docs/method/phased-pilot.md。
克隆（Clone） M9
仓库在你电脑上的一份副本，带有完整历史和指向原仓库的链接，用 gh repo clone owner/name 或 git clone <address> 生成。它会落在你当前所在的文件夹里。出处：lab.md，第 3 步。
免费档与免费开源定位（Free tier vs. free-and-open positioning） M7
免费档是对付费产品的限额；免费开源是附带商业模式的 $0 价格。ListenToMe 属于后者；Natively 那一行两者兼有。
内容即代码（Content as code） M6

在终端里操作 GitHub 的命令：登录、创建仓库、克隆。用 winget install --id GitHub.cli --source winget 或 brew install gh 安装。出处：setup/check-setup.sh。

macOS 包管理器（Homebrew） M9
macOS 的包管理器。安装时会顺带装上 Apple 的 Command Line Tools，在 Apple 芯片的 Mac 上位于 /opt/homebrew。出处：lab.md，第 1 步。

项目宪章的 Context A：一个智能体挑选优先级最高的未完成规格，完成*全部*验收标准，并报告 <promise>DONE</promise>。— SignUpFlow/.specify/memory/constitution.md。

W

Windows 包管理器（winget） M9
Windows Package Manager，随微软的 App Installer 一起提供；需要 Windows 10 1809 或更高版本。出处：lab.md，第 1 步。
