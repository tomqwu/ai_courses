# Deep-Read Report: ListenToMe (The Native On-Device AI App)

> Source: subagent deep-read of /Users/tomwu/ai_courses/ListenToMe (all claims grounded in files read directly from the repo).

## 1. What the product is, its differentiators, and the "3 types" lesson

**ListenToMe** (README.md) is a free, open-source (MIT), fully on-device meeting copilot for macOS 26+ with a companion standalone iOS 26 app. It captures two audio channels — your microphone (labeled **You**) and other participants' system audio via ScreenCaptureKit (labeled **Others**) — transcribes live on-device, and streams real-time AI help through **Ollama** (local models by default; Ollama Cloud optionally, with your own key). Stack: Swift 6 / SwiftUI / `@Observable` / Swift Concurrency; all testable logic lives in a pure SwiftPM package `ListenToMeCore` (33 modules, ~3,400 lines) with **96% test coverage** (95% CI floor).

**Differentiators** (README "Why ListenToMe" + `docs/competition-analysis.md`):
- **On-device & private** — transcription runs locally (Apple SpeechAnalyzer); with a local Ollama model, audio and transcript never leave the Mac.
- **Bring your own model** — any Ollama model, local or cloud, instead of one undisclosed backend LLM.
- **Multi-pane, multi-model** — four panes (Transcript, Listener, Quick, Deep); each AI pane has its own model dropdown with "good for" hints, so you can run a fast model for live notes and a stronger one for deep analysis on the same conversation.
- **Multi-purpose presets** — 18 use-case presets plus file/folder reference context.
- **Free & open-source** — no subscription, code open for inspection.

**The "3 types" lesson.** `docs/competition-analysis.md` sorts the market into shapes: (1) **bot-joining cloud note-takers** (Otter, Fireflies, Fathom, Fellow, tl;dv); (2) **bot-free desktop capturers / real-time overlays that still run cloud ASR + cloud AI** (Granola, Superpowered, Cluely and interview-assist tools — "local-first" marketing where only *capture* is local); (3) **genuinely on-device tools** (MacWhisper, Natively, ListenToMe). For a course, this is a teachable taxonomy of AI app types, and ListenToMe is the complete specimen of type 3 — the **native on-device AI app**: privacy verified in engineering, model choice exposed to the user, and trust made explicit through a 3-way mode switch (**Local only / Cloud / AI off**) rather than a marketing sentence. The spec itself framed the product as "the transparent, on-device, BYOK inverse of Cluely. Not covert, not cloud-hoarded, not subscription-locked" — with a visible recording indicator (never stealth) as a non-negotiable non-goal.

## 2. The full AI architecture

Layered design: **pure core behind protocols + thin platform glue**. `Sources/ListenToMeCore` holds all logic; `App/` holds AVFoundation/ScreenCaptureKit/Speech/SwiftUI glue.

- **Capture** (`App/DualChannelCapture.swift`): AVAudioEngine mic tap + `SCStream` system audio, both converted to mono Float PCM and tagged `SpeakerSource` (.you/.others) as `AudioChunk`s on `AsyncStream`s.
- **Three transcription engines behind one `Transcribing` protocol** (core `Transcriber.swift`; selected via `makeTranscriber`):
  - **SpeechAnalyzerTranscriber** (default; macOS 26 SpeechAnalyzer; transcribes both channels concurrently; downloads its language model on first use *before* capture starts, cancellably).
  - **SpeechRecognizerTranscriber** (legacy `SFSpeechRecognizer`, one per source; can hit the process-global limit `kAFAssistantErrorDomain 1100`).
  - **WhisperKitTranscriber** (opt-in; true Mandarin↔English code-switching Apple's Speech can't do; finalized segments only; its timestamps are what per-line speaker attribution requires).
- **VAD** (`VAD.swift`): pure `rms(of:)` + `VADSegmenter` (defaults: speechThreshold 0.02, 0.8 s trailing silence) fires utterance boundaries exactly once.
- **ConversationStore**: `@Observable` finalized-utterance log + current partial; `recentContext(maxChars:)` keeps the newest segments that fit a budget (default 4,000 chars), always at least one.
- **ContextEngine**: `buildContext` trims and nil-normalizes notes, rolling summary, responseLanguage, references, personaGuidance; `shouldFireProactive` fires only for finalized `.others` segments passing question detection, debounced (default 8 s).
- **QuestionDetector**: deliberately simple heuristic — trailing "?", leading interrogatives (what/why/how/…), word-boundary phrase cues ("can you", "any thoughts", "walk me through"). Swappable by design.
- **Prompt building** (`Prompt.swift`): `PromptBuilder` with three base system prompts — `systemPrompt` (anti-preamble: "No preamble, no 'As an AI'… 1-3 short sentences"), `listenerSystemPrompt` (rolling summary + decisions/actions/open questions; "Never invent an owner, deadline, agreement, or completion. Mark missing details as unstated"), `deepSystemPrompt` (depth over brevity). `systemWithDirectives` appends the preset's `personaGuidance` and a response-language directive to **every** pane — the same path manual panes and automatic reviews use. `ResponseAction` has 9 variants (answerQuestion, recap, followUp, proactive, actionItems, clarify, counterpoint, keyTerms, draftReply), each with Quick and Deep instruction variants.
- **Per-role model routing**: `CopilotRole` (listener/quick/deep); `MeetingSession` keeps `models`, `providers`, `responseTasks`, `responseGenerations` dictionaries per role; `setModel` rebuilds that role's provider and cancels its in-flight stream via generation tokens (a stale answer can't arrive under a new model's name). `ModelRouter` remains the MVP-era provider registry (`register`/`setActive`/`stream`).
- **ModelRanking** (pure): token-prefix matching (rejects "gemini" ⊃ "mini" false hits), capability weights (parameter size; pro/reason/code up; flash/mini/lite down), `roleDefaults` assigning Quick the fastest, Deep the strongest, Listener a distinct fast model — **local-first**: `:cloud` models are filtered out of auto-selection unless no local model exists. Curated "good for" hints for ~20 model families.
- **OllamaProvider**: NDJSON streaming over `/api/chat`; injectable `lineSource` for tests; parses in-stream `{error:...}` events; typed `OllamaStreamError` (.server/.incomplete/.empty) so truncated or empty streams can't finish as success; `LLMRequest.Purpose.quickEvaluation` forces `think:false`, temperature 0, 3,072 output tokens (a budget raised after live GLM testing exposed planning preambles exhausting a 1,600-token cap).
- **Listener→Quick/Deep grounding**: the last *completed* listener summary is kept separate from the live display value and injected into Quick/Deep prompts, so proactive answers never read an in-flight empty summary.
- **Shared live-summary engine** (`LiveSummaryScheduler`, `QuickSummaryContext`, `QuickSummaryReader`, `AutomaticReviewCoordinator`; `docs/SHARED-LIVE-SUMMARY.md`): shared by macOS and iOS; 5-second batches, 24-char eligibility threshold, no polling during silence, bounded backoff, 30 s/16 KiB response caps; medium/high-confidence Quick evaluations enqueue Summary (min 30 s apart) and Deep (min 60 s) full reviews serially; attribution labels every line `"<speaker>: <text>"`, marks typed notes as `Notes:` (never as speech), and repeats the label on every 600-char chunk.
- **Speaker diarization** (experimental, opt-in, WhisperKit-only): App-owned `SpeakerAudioBuffer` resamples the Others channel to 16 kHz mono (capped ~2 hours); a `SpeakerDiarizer` actor runs FluidAudio (CoreML Pyannote) about every 20 s plus a final pass after Stop; Core's pure `SpeakerStats`/`SpeakerLabeling`/`SpeakerIdentityTracker` aggregate talk time and match identities across passes by shared audio timing. Names flow into prompts, refreshed summaries, search, and Markdown/PDF exports. Core stays free of the FluidAudio dependency — only pure values cross the boundary.
- **Persistence/export**: `SessionArchive`/`SessionStore` (atomic saves, ~1/s autosave checkpoints), `SessionSearch` (⌘F history), `SessionExporter` (Markdown/recap/PDF).

## 3. Specs → plans → implementation → testing → release (superpowers workflow)

The v1-marathon spec phases work (0: competition research ≥8 competitors; 1: presets; 2: backlog incl. WhisperKit; 3: beautification; 4: docs; 5: signed+notarized release), each with acceptance criteria. The preset and diarization plans follow the same task pattern; the diarization plan shows the core-purity rule (FluidAudio stays out of Core) and a controller note splitting implementer vs. reviewer roles.

**How AI agents were used:** every plan opens "For agentic workers: REQUIRED SUB-SKILL superpowers:subagent-driven-development"; one PR per task; **Codex review before every commit** with blocking issues resolved first; `AGENTS.md`/`CLAUDE.md` codify the agent's definition of done: implement → test/lint/coverage → verify in the *installed* app (for audio: actual system-audio transcription labeled OTHERS, "a permission toggle is not proof") → bump version → push, CI, PR → publish the signed notarized DMG targeting the exact source commit → download the published asset and verify its checksum. Stale docs are a "Definition-of-Done failure"; the backlog lives in GitHub Issues, not markdown.

**Testing discipline:** CI on `macos-26` runners has three jobs — macOS app build, iOS app build (both verify the checked-in dependency lock via `diff`), and the `ListenToMeCore` suite with a **95% coverage floor** enforced by `scripts/check-coverage.sh` (llvm-cov line coverage). Current badge: 96%; 36 test files, ~290 test functions. `make pre-push` is the CI-equivalent gate (lint + tests + build); `make validate-local` adds iOS simulator UI tests, release-helper tests, and the real Ollama contract. **`make e2e` runs a real LLM contract test** through the actual `OllamaProvider` against the local Ollama server, auto-selecting an installed chat model (`LTM_E2E_MODEL` override) — because CI can't reach audio hardware or a daemon; mic/system-audio/live-STT acceptance stays in `docs/manual-smoke-test.md`.

**Release discipline:** `docs/RELEASING.md` — `make release` builds Release config with locked dependencies, deep-codesigns with Developer ID, packages a DMG, notarizes via notarytool, staples; publish with `gh release create` targeting the exact commit; **dev and release apps use separate bundle ids** because macOS TCC keys grants by bundle id *and* signing requirement — shared ids would silently invalidate each other's permissions. iOS ships through TestFlight (`docs/IOS-RELEASING.md`, `make ios-testflight` via an App Store Connect API key); AGENTS.md records a successful agent-run upload (iOS 1.4.0 build 11, September 12, 2026) and insists physical-device acceptance is kept separate from upload success.

**The honest review gate** (`docs/reviews/2026-09-10/design-and-gap-review.md`): a 34-item gap inventory (G01–G34) with P0/P1/P2 priorities and evidence classes (verified / source / validate) that recommended **not** promoting 1.3.0 as a validated production release despite 215 passing tests and 97.24% coverage — calling out silent cloud routing, missing durable checkpoints, discarded storage errors, ignored in-stream Ollama errors, and misleading capture health. Later releases closed these P0s (README now documents explicit AI routing, autosaving checkpoints, Save/New/History).

## 4. Privacy/on-device design principles and local-only enforcement

**Principles** (CLAUDE.md): "On-device · private · bring-your-own-model · free & open-source. Anything that would send data off-device **by default** is out of scope." Plus: visible recording indicator, never covert; explicit consent for every off-device hop; truthful claims.

**How local-only was engineered** (a superb trust module):
- `AIProcessingMode` (off / local / apple / cloud) with truthful labels ("Ollama Cloud — sends transcript and context"). Adding an API key alone never switches modes.
- `ModelPrivacy.isVerifiedLocal` — **fail-closed** verification of Ollama's `/api/show` metadata on every request: `remote_host` and `remote_model` must be absent, `details.format` and `model_info` non-empty. A localhost URL or model *name* is insufficient, because a local daemon can serve cloud-backed aliases.
- In local-only mode `OllamaProvider` additionally requires the host to be `localhost`/`127.0.0.1`/`::1` and installs a `RejectRedirects` URLSession delegate — HTTP redirects are refused so meeting text can never be silently forwarded.
- `ModelRanking.roleDefaults` filters `:cloud` models from auto-selection; cloud is auto-picked only when no local chat model exists (i.e., the user set a cloud key, opting in).
- Trust boundaries stated honestly: local-only "trusts the installed local Ollama service and its metadata" (README). iOS never sends a saved Ollama Cloud key to a user-entered self-hosted server URL; a failed Apple-Intelligence Auto experiment (3/7 quality cases) was isolated outside both app targets rather than shipped.
- **AI off** keeps capture, transcription, and saving working — native capture stays useful when AI is unavailable.

## 5. Teachable takeaways (each can anchor a lesson/lab)

1. **Build a per-role model router** — `CopilotRole.swift`, `MeetingSession.swift` (per-role models/providers/tasks/generations; `setModel` cancels the superseded stream), `ModelRouter.swift`, `ModelRanking.swift` (`roleDefaults`, token-prefix matching, "good for" hints). Lab: three panes, three models, one conversation.
2. **Harden a local-only mode against cloud model aliases** — `ModelPrivacy.swift` (`isVerifiedLocal`), `OllamaProvider.swift` (localhost check, `RejectRedirects`, per-request verification), `ModelRanking.swift` (local-first auto-defaults). Lab: red-team a local daemon alias.
3. **Separate testable core from platform glue with protocols** — `ListenToMeCore` (SwiftPM, 96%) vs `App/`; `Capture.swift`/`Transcriber.swift`/`LLMProvider.swift` seams; the diarization plan's rule that FluidAudio stays out of Core. Lab: unit-test an orchestrator with mock capture/transcriber/LLM (`Mocks.swift`).
4. **Write specs and plans an AI agent can execute** — `docs/superpowers/` specs (protocol-level interfaces, non-goals, risks) and plans (checkbox TDD tasks, exact file paths, self-review verifying spec coverage). Lab: have students generate and then hand-correct a plan.
5. **Enforce a coverage floor in CI** — `scripts/check-coverage.sh` (llvm-cov, 95% floor), `.github/workflows/ci.yml` (3 jobs + dependency-lock `diff`). Lab: add a gate to a sample package.
6. **Contract-test the real LLM outside CI** — `make e2e`, `OllamaContractE2ETests.swift`, `SummaryContractE2ETests.swift`, `LTM_E2E_MODEL`; CI covers headless logic, the local Mac covers real-model and audio acceptance.
7. **Treat prompts as pure, unit-tested builders** — `Prompt.swift` (`systemWithDirectives`, the listener "never invent an owner" contract, 9 actions), `PromptBuilderTests.swift`, `PresetCatalog.swift` (persona guidance threading through `ContextEngine` → prompts, tested end-to-end).
8. **Cheap proactive triggers: heuristics + VAD + debounce** — `QuestionDetector.swift`, `VAD.swift`, `ContextEngine.shouldFireProactive`; the spec's reasoning for keeping it swappable.
9. **Fail closed on streaming errors** — `OllamaStreamError` (.server/.incomplete/.empty), in-stream `{error:...}` parsing; contrast with gap G06 in the design review, which found the old provider finishing truncated streams as success.
10. **Institutionalize honest self-review** — `docs/reviews/2026-09-10/design-and-gap-review.md`: gap inventory with priorities and evidence classes; "do not promote 1.3.0"; then verify the P0s actually closed in shipped docs. Great module on shipping ethics + release gates.
11. **Separate dev/release identities to respect OS privacy grants** — `docs/RELEASING.md` bundle-id split (TCC keyed by bundle id + signing requirement), shared Keychain service, isolated history.
12. **Automate distribution as part of definition-of-done** — AGENTS.md six-step done-list with checksum verification and exact-commit targeting; TestFlight uploads via API key (`docs/IOS-RELEASING.md`). Lab: script a notarized release end-to-end.

(Bonus: **scope pivots leave artifacts** — the original spec planned Claude/OpenAI/DeepSeek providers; the shipped product is deliberately Ollama-only because "Ollama Cloud already exposes GPT/DeepSeek/Qwen through one key," yet `DeepSeekProvider.swift` + tests still sit in Core — a teachable moment about decision drift and dead code.)
