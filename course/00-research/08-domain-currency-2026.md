# Research: Is the Curriculum Current? A Domain-by-Domain Check (September 2026)

> Compiled 2026-09-17 by web research plus direct reads of the three case-study repos, for the platform
> review (`04-platform-review-2026.md`). Where only a search-engine summary of a page was readable, the
> claim says *(via search summary)* and is lower confidence. No version number or date below is invented;
> where a number comes from a secondary blog it is marked. The "verification to-dos" at the end are the
> claims the instructor should confirm against primary sources before teaching them.

## Domain 1 — Native on-device AI apps (ListenToMe / TinyCopilot)

**What the course assumes** (from `ListenToMe/README.md`): macOS 26+ / iOS 26+, Swift 6, Apple
SpeechAnalyzer by default with optional WhisperKit, Ollama (local or Ollama Cloud) with per-pane model
routing, a fail-closed local-only mode that verifies model metadata, a 95% coverage floor, signed and
notarized DMGs.

**What changed.**

- **Apple's Foundation Models framework became provider-agnostic at WWDC26.** Apple's guide: "You can now work with any language model, including Apple Foundation Models, cloud models like Claude and Gemini, or any other provider that conforms to the Language Model protocol", plus multimodal prompts, Vision-framework tools, "Dynamic Profiles" to swap models inside a session, and a new **Evaluations framework** "to verify that your AI features behave correctly" ([Apple WWDC26 ML guide](https://developer.apple.com/wwdc26/guides/machine-learning/); [Apple Intelligence guide](https://developer.apple.com/wwdc26/guides/apple-intelligence/)). Session 339 shows the protocol: `LanguageModel` and `LanguageModelExecutor` (`prewarm`, `respond(… streamingInto:)`), targeting `.macOS(.v27), .iOS(.v27)` ([session 339](https://developer.apple.com/videos/play/wwdc2026/339/)). Session 241 adds context-size/token-count APIs, an `fm` CLI on macOS 27, a Python SDK, and the core framework open-sourced for Linux ([session 241](https://developer.apple.com/videos/play/wwdc2026/241/)). *Vendor sessions; independent benchmarks not found.*
- **Private Cloud Compute is now a zero-cost tier for small apps.** Apple: apps in the Small Business Program with under 2M first-time downloads can use the next-generation models on Private Cloud Compute "at no cloud API cost", 32K context, per-user daily quota metered on the iCloud account ([Apple Intelligence guide](https://developer.apple.com/wwdc26/guides/apple-intelligence/); [session 319](https://developer.apple.com/videos/play/wwdc2026/319/)). This changes the "local vs cloud" story and the pricing module.
- **Core AI** is a new on-device framework beside Core ML and MLX; MLX gained Metal 4 and GPU Neural Accelerator support ([WWDC26 ML guide](https://developer.apple.com/wwdc26/guides/machine-learning/)). Third-party write-ups describe a ~20B sparse on-device model activating 1–4B parameters ([callstack, via search summary](https://www.callstack.com/blog/on-device-ai-after-wwdc-2026-whats-new)) — **unverified; do not teach the parameter count without Apple's paper.**
- **Speech.** SpeechAnalyzer/SpeechTranscriber is the mainstream on-device choice; hands-on tests report it materially faster than Whisper large-v3-turbo on long files ([MacStories, via search summary](https://www.macstories.net/stories/hands-on-how-apples-new-speech-apis-outpace-whisper-for-lightning-fast-transcription/)); limits: no custom vocabulary, no server fallback ([forasoft](https://www.forasoft.com/blog/article/speech-recognition-with-neural-networks-on-ios-1621)). WhisperKit is maintained and Argmax now also ships TTSKit and SpeakerKit ([argmaxinc](https://github.com/argmaxinc/WhisperKit)).
- **Local runtimes.** Ollama moved Apple-silicon inference to MLX (0.19 preview, 2026-03-31, reported ≥32 GB unified-memory requirement) ([MacRumors, via search summary](https://www.macrumors.com/2026/03/31/ollama-now-runs-faster-apple-silicon-macs/)); a secondary blog says v0.30 made MLX the default ([runaihome, unverified](https://runaihome.com/blog/ollama-v030-mlx-stable-upgrade-2026/)). LM Studio 0.4.x ships llama.cpp and MLX engines and an OpenAI- *and* Anthropic-compatible local API ([codersera, secondary](https://codersera.com/blog/lm-studio-complete-guide-2026/)).
- **Small models.** Gemma 4 (Apr 2026): E2B/E4B/26B-A4B/31B, Apache 2.0, audio input on the E series ([Edge AI & Vision Alliance](https://www.edge-ai-vision.com/2026/04/google-pushes-multimodal-ai-further-onto-edge-devices-with-gemma-4/)); Qwen3.5 (Feb 2026) with a 0.8B–9B small series ([MarkTechPost](https://www.marktechpost.com/2026/03/02/alibaba-just-released-qwen-3-5-small-models-a-family-of-0-8b-to-9b-parameters-built-for-on-device-applications/)); Phi-4-mini remains the "8 GB machine" pick ([sitepoint](https://www.sitepoint.com/best-local-llm-models-2026/)). The course's `qwen3:0.6b` still works as a lab model; the *model matrix* in the lessons is what ages.
- **Other platforms.** Windows ML (ONNX Runtime based) is GA since Sept 2025 with Foundry Local on top ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/overview)); Android ML Kit GenAI APIs on AICore, with a lower-level developer preview ([Android Developers](https://developer.android.com/ai/gemini-nano)).
- **App Store and privacy rules.** Guideline 5.1.2(i) (13 Nov 2025) requires clear disclosure and explicit permission before sharing personal data with "third-party AI" ([Apple Developer News](https://developer.apple.com/news/?id=ey6d8onl)); the 8 June 2026 update added DPLA §3.3.11(A) "requirements for use of Foundation Models framework" ([Apple Developer News](https://developer.apple.com/news/?id=a233fmpw)). Apps uploaded from April 2027 must use the OS 27 SDKs. No notarization changes were found ([eclecticlight, via search summary](https://eclecticlight.co/2026/01/17/whats-happening-with-code-signing-and-future-macos/)). EU AI Act Article 50 transparency duties applied from 2 Aug 2026 ([EC FAQ](https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act)).

**Stale / missing / still correct.**

- *Stale:* "Foundation Models = Apple's on-device model only" — it is now a provider-agnostic protocol; an Ollama/MLX backend can be exposed as a `LanguageModel` provider.
- *Stale:* cloud as strictly "leaves the device = privacy loss". Private Cloud Compute is free for small apps and Apple positions it as privacy-preserving; fail-closed local-only should be taught as a **three-tier policy** (on-device / PCC / third-party cloud).
- *Stale:* Ollama-on-Metal performance assumptions; MLX is the Apple-silicon path, with memory-floor caveats.
- *Missing:* Apple's Evaluations framework and `fm` CLI; Gemma 4 E-series and Qwen3.5-small in the model list; the 5.1.2(i)/DPLA consent screen as a shipping requirement; any Windows/Android equivalent so the archetype is not Apple-only.
- *Still correct:* SpeechAnalyzer-first with WhisperKit fallback; verifying model metadata and refusing redirects in local-only mode; the notarized DMG process; Swift 6 strict concurrency.

**Curriculum updates (Domain 1).** (1) A lesson "implement a `LanguageModel` provider" wrapping Ollama/MLX so per-role routing uses one API for on-device, PCC and local models. (2) Rebuild TinyCopilot's quality lab around Apple's Evaluations framework with promptfoo as the cross-platform equivalent. (3) Replace the model matrix with Gemma 4 E2B/E4B, Qwen3.5 0.8B–9B, Phi-4-mini. (4) A "privacy tiers + consent UX" segment mapping local-only / PCC / third-party cloud to 5.1.2(i), DPLA 3.3.11(A) and Article 50. (5) A short Windows ML / ML Kit comparison.

## Domain 2 — Spec-driven agentic SaaS (SignUpFlow)

**What the course assumes** (from `SignUpFlow/README.md`): FastAPI + SQLAlchemy 2.0 + JWT + HTMX + Flutter, org-level isolation, constitution + `AGENTS.md` + `CLAUDE.md`, spec-kit artifacts, seven local test tiers, playbooks with coverage manifests, and "GitHub Actions is not test or code-review evidence".

**What changed.**

- **GitHub spec-kit hit 1.0.** v1.0.0 on 2026-08-21, v1.0.7 on 2026-09-15; the loop is now `/speckit-constitution → specify → plan → tasks → implement → converge` (repeat implement → converge until converged), with opt-in extensions, and the legacy `--ai` flags removed in v0.10 in favour of `--integration` ([releases](https://github.com/github/spec-kit/releases); [README](https://github.com/github/spec-kit); [upgrade guide](https://github.github.com/spec-kit/upgrade.html)). The artifact set (spec/plan/research/data-model/contracts/tasks) is unchanged, so the course's structure is right; the command names and the converge step are not.
- **AGENTS.md is a foundation-governed standard.** MCP, goose and AGENTS.md were contributed to the Linux Foundation's Agentic AI Foundation (Dec 2025); AGENTS.md reportedly has 60k+ adopting projects ([CIO Dive](https://www.ciodive.com/news/big-tech-develop-open-standards-agentic-ai/807608/); [agents.md repo](https://github.com/openai/agents.md)). Nuance: **Claude Code reads `CLAUDE.md`, not `AGENTS.md`**; Anthropic recommends an `@AGENTS.md` import or a symlink so both tools share one source ([Claude Code memory docs](https://code.claude.com/docs/en/memory)).
- **Official CLAUDE.md guidance:** keep it under ~200 lines, "for each line, ask: would removing this cause Claude to make mistakes?"; move procedures to skills, path-scoped rules to `.claude/rules/`, deterministic enforcement to hooks ("CLAUDE.md instructions are advisory, hooks are deterministic"); give the agent a check it can run ([best practices](https://code.claude.com/docs/en/best-practices)). The course's M1 rules ("imperative, verifiable, under 200 lines") match; the hooks/rules/skills split is missing.
- **MCP 2026-07-28 spec** — the "largest revision since launch": stateless core, multi-round-trip requests, OAuth hardening, Dynamic Client Registration deprecated in favour of Client ID Metadata Documents ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)). NSA/CISA published MCP security design guidance in June 2026 ([media.defense.gov](https://media.defense.gov/2026/Jun/02/2003943289/-1/-1/0/CSI_MCP_SECURITY.PDF)).
- **Security.** OWASP GenAI LLM Top 10 **2026** was published 2026-08-04 ([OWASP repo](https://github.com/OWASP/www-project-top-10-for-large-language-model-applications)); secondary coverage says prompt injection and sensitive-information disclosure keep the top two spots and Excessive Agency rose to third, and there is a separate Top 10 for Agentic Applications ([ReversingLabs, via search summary](https://www.reversinglabs.com/blog/owasp-top-10-for-llm-apps-excessive-agency)). Peer-reviewed work now targets prompt injection in AI dev tools themselves ([arXiv 2603.21642](https://arxiv.org/pdf/2603.21642)). Multi-tenant guidance stresses that row-level security "does not protect data once it enters an LLM context window" ([DeepInspect, vendor](https://www.deepinspect.ai/blog/ai-tenant-isolation)).
- **Evals.** The 2026 pattern is a CI-gating framework (promptfoo / DeepEval / RAGAS) plus a platform (Braintrust / LangSmith / Arize / Langfuse) ([comparison](https://majesticlabs.dev/blog/202608/13-llm-evaluation-tools-compared-aug-2026)). Verified: promptfoo's README states "Promptfoo is now part of OpenAI… remains open source and MIT licensed" ([promptfoo](https://github.com/promptfoo/promptfoo)).
- **Productivity evidence (independent).** METR 2025: 16 developers, 246 tasks, 19% *slower* with AI while believing they were 20% faster ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). The Feb 2026 update (57 developers, 800+ tasks): returning developers ~18% slower (CI −38% to +9%), new recruits ~4% slower (CI −15% to +9%) ([METR update, via search summary](https://metr.org/blog/2026-02-24-uplift-update/); [summary](https://blog.robbowley.net/2026/04/04/metrs-developer-productivity-research-2026-update/)). DORA 2025: AI adoption correlates with higher throughput *and* higher instability; "AI amplifies" existing practices ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report)). The course already carries METR in `m06/evidence-dataset.md`; it does not yet use it to motivate M1's governance.
- **"No CI by choice."** Defensible as pedagogy (local evidence, reviewed SHAs) and consistent with "have the agent show evidence rather than asserting success". But the 2026 norm is the opposite: every major agent runs in the cloud and opens PRs, and `claude -p` is designed for "CI, pre-commit hooks, or scripts". Teach it as a documented trade-off with an exit path, not as the default.
- **Competing frameworks.** BMAD, AWS Kiro, OpenSpec, GSD; comparisons note they converge on the same four-phase loop ([DEV](https://dev.to/willtorber/spec-kit-vs-bmad-vs-openspec-choosing-an-sdd-framework-in-2026-d3j)).

**Stale / missing / still correct.**

- *Stale:* spec-kit command names and the absence of `converge`; duplicating rules across `AGENTS.md` and `CLAUDE.md` (official guidance is import/symlink); any MCP example relying on persistent sessions or DCR.
- *Missing:* hooks / rules / skills / subagents decision table; OWASP GenAI 2026 and the Agentic Top 10; tenant-scoped retrieval; evals as an eighth test tier; the METR/DORA evidence base as the *reason* for governance.
- *Still correct:* the artifact set; constitution-first; evidence-based acceptance with manifests; JWT + org isolation as a baseline (with a caveat on HS256 shared-secret signing in multi-tenant contexts).

**Curriculum updates (Domain 2).** (1) Re-record the spec-kit walkthrough on v1.0.x. (2) Restructure M1.1 as "one `AGENTS.md`, imported by `CLAUDE.md`" plus a hooks-vs-skills-vs-rules table. (3) Add an eighth test tier: LLM evals with a red-team suite mapped to OWASP GenAI 2026. (4) Add a "governance evidence" segment using METR 2025/2026 and DORA 2025. (5) Reframe "no CI" as an ADR with the 2026 counter-norm and a migration path.

## Domain 3 — Expertise content product (ai_qe)

**What the course assumes** (from `ai_qe/README.md`): Jekyll site, narrated decks with synchronized captions, per-claim citations, `_data/release.yml` editions with immutable releases, Playwright QA, illustrative-not-client scenarios, a consulting funnel.

**What changed.**

- **Discoverability has structurally changed.** Ahrefs (Feb 2026, via TNW) associates AI Overviews with a 58% CTR reduction for top-ranking pages, up from 34.5% in 2025 ([TNW](https://thenextweb.com/news/google-ai-overviews-publisher-links-search-traffic)); a randomized field experiment with 1,065 Chrome users found organic clicks fell 39.8% when an AI Overview appeared ([PPC Land](https://ppc.land/researchers-find-google-ai-overviews-cut-publisher-clicks-39-8/)); Chartbeat reports Google referrals to 2,500+ news sites down 33% in 2025 ([SEJ](https://www.searchenginejournal.com/impact-of-ai-overviews-how-publishers-need-to-adapt/556843/)). Vendor "GEO" guides converge on: cite authoritative sources, quote named experts, add specific statistics, keep content fresh. `llms.txt` has weak evidence: Google's John Mueller says no major AI service uses it and an Ahrefs crawl found 97% of `llms.txt` files receive zero requests ([LLM Pulse, secondary](https://llmpulse.ai/blog/geo-guide/)). A site that is already claim-level cited, statistic-dense and fresh is what the engines reportedly reward.
- **AI engines mis-cite.** Tow Center (Mar 2025): across 1,600 queries on eight AI search engines, over 60% failed to identify the source correctly ([Nieman Lab](https://www.niemanlab.org/2025/03/ai-search-engines-fail-to-produce-accurate-citations-in-over-60-of-tests-according-to-new-tow-center-study/)). Stable permalinks per claim and per edition — which ai_qe has — are a defensive asset.
- **Provenance tooling.** C2PA 2.4 (2026-04-21) with a conformance programme; manifests can be embedded in PDFs; EU AI Act Article 50 and California SB 942 require machine-readable disclosure of AI-generated content ([C2PA explainer](https://spec.c2pa.org/specifications/specifications/2.4/explainer/Explainer.html)). Since ai_qe's narration and illustrations are synthetic, disclosure and marking is a compliance item ([EC FAQ](https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act); [Orrick](https://www.orrick.com/en/Insights/2026/08/EU-AI-Act-Transparency-Obligations-for-AI-Generated-Content-Article-50)).
- **Narrated decks are a commodity.** NotebookLM's "Cinematic Video Overviews" (2026-03-04) generate animated video from a PDF ([9to5Google](https://9to5google.com/2026/03/04/notebooklm-cinematic-video-overviews-ai-mode/)). The durable differentiator is the evidence chain and stable slide IDs, not the narration.
- **Editions.** No authoritative industry norm found; ai_qe's editioned immutable releases are ahead of common practice. The gap is a *machine-readable* manifest (C2PA or signed JSON) rather than a human-readable release note.
- **Jekyll** shows no deprecation signals and remains GitHub Pages' native generator.

**Stale / missing / still correct.**

- *Stale:* SEO-era assumptions about organic click volume; the launch module should assume 30–60% fewer Google clicks for informational content.
- *Missing:* a "publishing for AI engines" segment; Article 50 / C2PA disclosure for synthetic narration; a machine-readable edition manifest; a citation-resilience design framed with the Tow Center data.
- *Still correct:* four claim levels and per-claim provenance; editioned immutable releases; the self-audit; illustrative-not-client scenarios.

**Curriculum updates (Domain 3).** (1) A "publishing for AI engines" lesson; drop `llms.txt` or label it speculative. (2) A compliance checklist: Article 50 disclosure text, C2PA on PDF exports, synthetic-voice labelling. (3) Editions gain a signed machine-readable manifest (claim → source → level → hash). (4) Reframe "narrated deck" as a view over the evidence graph, with a NotebookLM comparison. (5) Measure AI-engine citations, not just analytics sessions.

## Cross-cutting — monetization and launch

- **Pricing norms.** Secondary reports say seat-only pricing fell while hybrid base-plus-usage and outcome models rose to ~41–43% of AI SaaS; Intercom's $0.99/resolution is the canonical outcome example ([Monetizely, vendor](https://www.getmonetizely.com/blogs/the-2026-guide-to-saas-ai-and-agentic-pricing-models)). Teach the direction, not the exact percentages.
- **BYOK** is a default expectation in developer tools; it "is not local — your prompt still travels to a cloud provider" ([Scribelet](https://scribelet.app/blog/byok-ai)). ListenToMe's Ollama Cloud key path is BYOK; the course should separate BYOK from local-only in privacy claims and note that BYOK to third-party AI still triggers 5.1.2(i) consent.
- **Apple's free PCC tier changes unit economics** for sub-2M-download apps: zero inference cost and a user-metered quota with an iCloud+ upsell hook ([session 319](https://developer.apple.com/videos/play/wwdc2026/319/)). A Mac/iOS-first product can price on features rather than tokens.
- **Selling AI features in 2026 is a compliance surface:** Article 50 disclosure, DPLA §3.3.11(A), 5.1.2(i) consent, and agent-tool credentials moving to OAuth 2.1 under MCP 2026-07-28.
- **Distribution:** launch playbooks that assume Google organic traffic need revising; AI-engine citation and owned channels (email, communities) should be primary.

**Cross-cutting updates.** (1) Replace M7.1's taxonomy with per-seat / usage / per-outcome / hybrid / BYOK-discount and a worked ListenToMe example using PCC's free tier. (2) A "privacy claims you can legally make" table: local-only vs PCC vs BYOK vs vendor cloud. (3) A launch-checklist item for AI-engine discoverability and disclosure artifacts. (4) An evidence-quality label on every market statistic in the course, mirroring ai_qe's four claim levels.
