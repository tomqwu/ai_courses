# 第 7 模块 — 变现：定价、包装与定位

> AI Product Studio（APS-3）的一部分 · 约 60 分钟 · 前置：第 1–6 模块

## 概览

第 1–6 模块构建了三个产品的可运行核心。第 7 模块为它们定价。这里的定价不是凭感觉拍板——它是一个从证据推导出来的工程决策：一张有来源的竞品表、一条算出来的成本底线（cost floor），以及买家可以审计的主张。每个数字都能追溯到一个你可以打开的仓库文件、本课程的研究（`course/00-research/`）、本课程自己的决策记录（`course/04-sales/pricing-and-platforms.md`），或者一个写明的假设——你要用自己带日期的数字把它替换掉。两个成本底线实例演示了算术；本课程自己的记录是第三个。

学完本模块，你能够根据竞争证据为每种产品原型（archetype）的产品**定价**，按渠道经济学**包装**产品并选择平台，并用诚实、有限定的主张来**营销**它（M7.1–M7.3）。实验 M7 把这一切应用到*你自己的*产品上（来自实验 M2、M4 或 M6）：一张有来源的定价表、一份决策工作表、一句定位一句话（positioning one-liner）、一个包装页，以及一次经得起怀疑派工程师审查的自我评审。

## M7.1 — 为三种产品原型定价（约 20 分钟）

### 目标

依据证据而不是直觉，为每种产品原型（archetype）选择定价模式：应用是一次性还是订阅；SaaS 按席位分档，付费路径在被证明之前一律门控；专业知识产品用一个分阶段的漏斗来销售测量。说出每一种应对重复成本的模式——按席位、按用量、按结果、混合、自带密钥（BYOK）折扣——各自匹配什么、惩罚什么。说明每个选择意味着谁付费，以及在哪个阶段付费。

### 讲解

**类型 1——成本怎样重复发生，就怎样定价。** 打开 `ListenToMe/docs/competition-analysis.md`，读价格列；条目遵循这个文件自己的不确定性约定——无法确认的细节标注为「大约」或「据报道」（文件开头，日期为 2026-09）。市场概况浓缩如下：

| 工具 | 定价模式 | 价格（2026，依据 `competition-analysis.md`） |
|---|---|---|
| Granola | 按用户/月 | 免费档；Business ~$14/用户/月；Enterprise ~$35/用户/月 |
| Otter.ai | 按用户/月 | 免费（300 分钟/月）；Pro ~$8.33–16.99/用户/月；Business ~$20–30/用户/月 |
| Fireflies.ai | 按席位/月 | 免费；Pro ~$10–18/席位/月；Business ~$19–29；Enterprise ~$39 |
| Superpowered | 按用户/月 | 免费（10 条笔记/月）；Basic $25/月；Pro $50/月 |
| Cluely | 按用户/月 | 免费 Starter；Pro $19.99/月；Pro + Undetectability $149.99/月 |
| MacWhisper | 一次性（直销） | 免费档；Pro ~€59（~$69）一次性；App Store $6.99/月–$99.99 终身 |
| Natively | 免费 + Pro | 个人免费；Pro 可买断或按年购买 |
| ListenToMe | 免费开源 | $0，MIT |

这个规律是结构性的，而不是风格上的。每个按月收费的工具都在云端运行每用户算力：Granola 把每场会议都送进第三方云端 ASR 和云端 LLM 摘要；Otter 在自己的服务器上运行自研的专有 ASR，再加上云端 LLM 洞察（见 `competition-analysis.md` 中各竞品的小节）。MacWhisper 完全在端侧运行 Whisper——每个用户的边际成本接近零——并且只收一次费。这条决策规则用一句话说就是：**如果你的每用户成本每月重复发生，就按月定价；如果不重复发生，订阅就成了一笔税，你的用户可以拿它来审计你。**

**应对重复成本的五种模式。** 没有重复成本，就停在一次性定价（one-time pricing）或免费 + Pro（MacWhisper、Natively）。有重复成本，就从五种里选；按成本以及买家获得的价值随什么增长来选：

| 模式 | 匹配 | 惩罚 | 示例 |
|---|---|---|---|
| 按席位 | 随每个使用者增长的价值和成本 | 低价值席位的增长（志愿者、只读查看者）；共用席位 | Granola Business ~$14/用户/月（`ListenToMe/docs/competition-analysis.md`）；SignUpFlow 的邀请就是计费事件 |
| 按用量 | 随消耗增长的成本：token、分钟、核心小时 | 买家的预算：无法预测的账单 | Otter 的免费档，300 分钟/月（同一张表）；GitHub Codespaces，每月 120 个免费核心小时，之后每个 $0.18（`course/00-research/05-platform-build-options-2026.md` §4，第三方） |
| 按结果 | 买家能计数的价值：一个已解决的工单、一个已填补的班次 | 卖方，每当归因有争议时 | Intercom 每次解决 $0.99（`course/00-research/08-domain-currency-2026.md`，跨领域部分；厂商博客，二手来源）；AI × QE 拒绝采用它（见下文） |
| 混合 | 一个可预测的基础费用，加上一笔你必须设上限的可变成本 | 简洁性：要解释两个数字，还有超额带来的意外 | Circle，$89/月加 0.5–2% 的交易费（05 §1，第三方）；下文的 Cloud 档 |
| BYOK 折扣 | 一笔你可以交给客户承担的推理成本 | 没有密钥的买家，以及任何「本地」的说法 | MacWhisper：用你自己的 API 密钥，或者付费的云端助手（表格，MacWhisper 一节）；ListenToMe：一个「用你自己的密钥」的云端选项（`ListenToMe/README.md:38-39`） |

BYOK 转移的是账单，而不是数据：它「不是本地的——你的提示词仍然会传到一个云服务商那里」（08，跨领域部分）。这是方向，不是事实：二手报道称，纯按席位定价在下降，而混合和按结果模式上升到约 41–43% 的 AI SaaS（同一节）。*证据：一家定价厂商的博客，二手来源——教方向，不教百分比。*

**「免费开源」的定位在哪里。** ListenToMe 定价 $0——MIT 许可证，「代码公开可查」——对阵价格列中从大约 $7 到 $149.99/月不等的付费档（`ListenToMe/docs/competition-analysis.md:20-35`）。免费是一种附带商业模式的价格，课程大纲点名了付费面：口碑漏斗（reputation funnel）、支持服务和一个 Pro 档（`course/01-design/curriculum.md`，M7.1）。口碑漏斗此刻就正在对你起作用——仓库、README、覆盖率徽章和涵盖 13 个竞品的分析，就是营销。Pro 档并不是假设：开源同类产品 Natively 的定价是「个人免费；Pro 可买断或按年购买」（`competition-analysis.md` 中的那一行）。开源不等于没有收入；它意味着付费档位于一个完整的免费核心*之上*，永远不是用来修补一个被削弱的核心。

**竞争对手不重建就无法追平的楔子。** 这张表点出了该品类的两种结构性张力：隐私与便利——「几乎每个商业产品都在云端处理音频、运行 AI，即使它自称『本地优先』——所谓本地部分通常只是音频*采集*」——以及替用户做主与开放，大多数产品把你锁定在一个不公开的转写引擎和一个摘要 LLM 上（`competition-analysis.md:14`）。ListenToMe 的「隐私 + 自带模型」定位之所以守得住，不是因为它是秘密，而是因为复制它会摧毁现有厂商的商业模式：它们的月费*支付的正是*云端 ASR 和云端 LLM 的算力；真正的端侧转写加上自带本地模型，会移除它们的订阅所定价的成本基础。一个持久的定价差异点，复制起来代价高昂的是**商业模式层面**，而不仅仅是代码层面。

**类型 2——按席位分档，并门控尚未证明的部分。** SaaS 的价值随组织规模增长，所以价格单位是席位。这里的定价课是 SignUpFlow 的功能门控（feature gating）模式。读 README 中 “Provider-backed Features” 那一段：计费路由仍然保留在代码库中的 `/api/v1` 下，短信路由在 `/api/sms` 下，「但两者默认都返回 404，由 `BILLING_ENABLED=false` 和 `SMS_ENABLED=false` 控制。付费计费和短信被推迟了；完整的排班工作流并不依赖它们。」（`SignUpFlow/README.md`）。`SignUpFlow/AGENTS.md` 把规则直接写了出来：「核心排班不得依赖任何一项付费集成。」

这句话排除了两种失败模式。第一，为一条还不可信的路径收费——把计费接进一个团队自己都还无法依赖的工作流。第二，门控核心工作流来逼用户升级——一个排班产品在你付费之前就不再排班。变现的顺序是：先让工作流可信，*然后*再打开开关。付费路径已经注册并由开关门控，所以日后的变现是以配置的形式发布，而不是做一场手术。

**邀请式增长的机制。** SignUpFlow 的组织通过邀请增长：`/auth/signup` 以原子方式创建组织及其第一位管理员，而「之后的所有成员都通过管理员创建的邀请加入」——「基于令牌的志愿者入驻」（`SignUpFlow/README.md`）。增长和计费是同一个事件：每位新成员都是被邀请的组织成员，所以按席位定价（per-seat pricing）跟踪的是真实采用，而发出邀请的人——管理员——就是买家。当你设计自己的 SaaS 增长循环时，让它产生计费事件。

**类型 3——销售测量的漏斗。** AI × QE 的漏斗在它自己的文件里就能看到：`ai_qe/index.md` 引导访客经过四张路径卡片（01/VISION、02/THE STORY、03/ARCHITECTURE、04/NEXT STEP），终点页面是 `ai_qe/discovery.md`——“Start with one workflow. Agree what better means.”——以一份问卷下载结束（`course/00-research/03-ai-qe-deep-read.md` §1）。各个阶段，以及每个阶段确认什么：

| 阶段 | 它是什么 | 它确认什么 |
|---|---|---|
| 1. 免费证据站点 | 116 张有引用的幻灯片、研究日志、公开的自我审计 | 信任——以零边际成本展示能力，并预先回答异议 |
| 2. 问卷 | v4 表单：36 个问题，按角色分流，定义成功的三个问题为单选 | 匹配度与范围——确认线索质量，并为基线模型提供输入 |
| 3. 固定费用探查 | “fixed-fee or capped discovery; separately capped pilot… No client price or start date has been agreed.”（`ai_qe/_data/engagement.json`） | 预算与发起人——一个有边界的首次付费合作 |
| 4. 有上限的分阶段试点 | 8–10 周，五个阶段（0–4），由发起人签字的继续/终止关口；在观察结果*之前*冻结验收标准；每组 ≥30 个可比任务；10%/15% 的工作量决策区间；最多一次 ≤4 周的延期 | 是否扩大规模 |
| 5. 验证 | 1–2 个季度，配合一份收益实现登记表 | 基于证据的续约 |

（所有行：`course/00-research/03-ai-qe-deep-read.md` §1、§4。）

**卖测量，不卖结果。** 这位顾问从不承诺节省数字：高管工作坊把问卷结果呈现为「问题而不是结论；还没有节省数字」（深度解读 §4）。保证定价诚信的机制是收益实现登记表（benefits-realization register）：它「把每一项声称的节省挂到一条由财务负责的预算行上」（深度解读 §4）——主张由客户*自己的*财务部门核对，所以一个夸大的数字不只是不诚实，而且是可以被查出来的。为你交付的东西定价——探查、基线、做了测量埋点的试点——让结果归于登记表。

### 行动步骤

为每种产品原型写一句话，写明**你的**产品的定价模式、谁付费，以及在哪个阶段付费——例如「下载时一次性 $X，因为我的每用户成本为零」，或者「按席位，在管理员邀请第四位成员时计费」。把它发到社区。实验 M7 会让你用一张表格为它辩护。

## M7.2 — 包装与平台（约 20 分钟）

### 目标

包装你的报价，让价格买到的是一次转变和一组产物，而不是视频时长；根据渠道经济学而不是习惯来选择平台；并在定任何价格之前，先算出成本底线（cost floor）——固定成本项加上一条推理成本线——以及它的保本点。

### 讲解

**直播班和自学版是两种产品。** 同样的内容是两种价值主张：研究给出的经验法则是「自学版 $97–297，或者作为 4 周直播班 $500–2,000+」（`course/00-research/02-course-market-research.md` §C，引用 ShopSpace）。直播班买家付费买的是实时授课、反馈和同伴——Maven 的基准正是为此定价：6–8 小时直播 + 1 个以上项目 → $800–1,200；8–12 小时 + 多个项目/结业项目 → $1,200–1,800；12–20 小时 + 多个项目 + 结业项目 → $1,800–2,450（§C）。

**直播价比例规则。** 自学版按直播档价格的一个比例定价：70–85%，*前提是它保留项目 + 异步反馈 + 社区*——如果这些一样都没保留，研究的结论是，光秃秃的视频库「根本不应该出售」（§C）。这条直播价比例规则（fraction-of-live-price rule）要防止的反模式，原文是：**「一堆 Zoom 录像不是自学课程」**（§C）。为产物和转变定价——评审、反馈、客观的实验检查清单——而不是为视频时长定价。这条规则可以推广到每种产品原型：一堆功能不是一个应用档位；一堆笔记不是一份简报。问一问买家花了这笔钱能*拿出*什么。

**课程市场 vs 自有平台。** Udemy：市场销售分成 37%（2025 年为每美元 32 美分），价格由平台控制在 $9.99，而且不能导出学员邮箱——「只用于获客/验证，永远不作为主渠道」（§D）。自有平台上的创作者收费 $50–200+，而 Udemy 的实际售价是 $10–15（§C、§D）。本课程自己的平台表——直播班用 Maven，自学版用 Thinkific/Teachable，引流产品用 Gumroad，社区用 Circle，“Never Udemy (primary)”——就是一个实例决策（`course/04-sales/pricing-and-platforms.md`）。

**类型 1 的应用商店 vs 直销。** MacWhisper 是渠道经济学的一个天然实验：同一个产品在 Gumroad 上一次性售价 ~€59/$69，在 App Store 上是 $6.99/月–$99.99 终身（`competition-analysis.md` 中的那一行）。商店带来触达和订阅预期，要抽成，并且拥有客户；直销给你利润和邮箱地址。直销并不是妥协——你从第 3 模块起就已经有了这套机制：签名、公证、装订票据的发布版本，以 DMG 形式发布，指向确切的提交（`ListenToMe/docs/RELEASING.md`）。按产品选择：要触达就上商店，要利润和客户关系就直销。

**先算底线，再定价格。** **固定底线**是在任何人购买之前你每月要付的钱：托管、数据库、邮件、开发者会员、摊销的构建时间。**推理成本线**是多一个用户每月让你多付的钱：

```
inference cost / user-month = calls per month × tokens per call ÷ 1,000 × rate per 1,000 tokens
contribution per sale       = price − payment fee − variable cost
break-even                  = fixed floor ÷ contribution, rounded up
```

每个输入要么是一个你能指出来的来源，要么是一个你写明的假设。本课程中没有任何文件记录了当前的模型 API 费率，所以两个示例都**假设每 1,000 个 token $0.005，输入和输出混合计算**——这是一个占位值，不是任何厂商的价格。去取你的服务商的价目表，标上日期，替换进去；这套算术对任何取值都成立。本课程自己的底线是最简单的情形，全部是固定成本：平台 + 社区 + 邮件 ≈ $80–130/月，所以在 $399 的自学档位，保本点是约 2 单/月（`course/04-sales/pricing-and-platforms.md`，“Cost floor”）。低于底线的价格不是价格；它是补贴。

**底线实例 1——把 TinyCopilot 做成产品（类型 1）。** 把实验 M2 的 copilot 作为一个带云端选项的 Mac 应用来卖。输入：

- **A1** 每个用户每月 20 场会议；**A2** 每场会议 30 次 Quick 回答——*假设*。上限是 450：一小时内每 8 秒防抖一次（`ListenToMe/Sources/ListenToMeCore/ContextEngine.swift:8`）。
- **A3** 每次回答 1,800 个 token：4,000 字符的窗口（`ListenToMe/Sources/ListenToMeCore/MeetingSession.swift:582-586`），按*假设的*每个 token 4 个字符计算，再加上*假设的* 500 个提示词 token 和 300 个回答 token。
- **A4** 每场会议一次回顾，26,000 个 token：100,000 字符的回顾预算（同样的行）÷ 4，再加 1,000 个输出——这是一个上限。
- **A5** 通过记录商户（merchant of record）销售，每单支付手续费 5% + $0.50（`course/00-research/05-platform-build-options-2026.md` §2，第三方）。
- **A6** 固定现金支出 $28.25/月：开发者会员 $99/年（`ListenToMe/docs/superpowers/specs/2026-06-18-listentome-design.md:259`），加上按 05 §1 中 ~$0–20/月区间的上限计算的托管费用。**A7** 构建时间 $333.33/月：160 小时 × $50 ÷ 24 个月——*假设*。

逐步算一遍。每场会议 30 × 1,800 + 26,000 = **80,000 个 token**；每用户每月 20 × 80,000 = **160 万**。如果由你付费，推理成本线是 1,600 × $0.005 = **每用户每月 $8.00**。谁付费取决于推理在哪里运行。**端侧**：你付 $0；用户用硬件来付，一个 4-bit 的 7B 模型大约需要 8–16 GB 内存（05 §4，第三方），而平台的端侧模型每次请求都是免费的（`course/00-research/06-competitive-landscape-2026.md` §3）。**BYOK**：你付 $0；客户的服务商为同样的 160 万 token 向客户收费——把这个公式印在密钥输入框旁边。**平台私有云**：在你符合资格期间，你付 $0。Apple 为首次下载量低于 200 万的 Small Business Program 应用提供一个私有云模型档位，「无云端 API 费用」，32K 上下文，每个用户有每日配额（`course/00-research/08-domain-currency-2026.md`，领域 1；厂商会议内容，未经独立确认）。26,000 个 token 的回顾放得下。

固定底线是 $28.25 + $333.33 = **$361.58/月**。一次性 $69 的 Pro——MacWhisper 的锚点——净得 $69 − $3.45 − $0.50 = **$65.05**：保本点是 $361.58 ÷ $65.05 = 5.6 → **每月 6 单 Pro**。一个托管云端档位扣除手续费后必须覆盖 $8.00，即 0.95 × 价格 − $0.50 ≥ $8.00，所以价格 ≥ **$8.95**。定价 $12 时，它贡献 $12 − $1.10 − $8.00 = **$2.90**；一个每月 40 场会议的用户要花掉 $16.00，所以这个档位要设上限。

| 档位 | 推理在哪里运行 | 你的成本 / 用户·月 | 价格 | 模式 |
|---|---|---|---|---|
| Free | 端侧 | $0 | $0 | 完整的免费核心 |
| Pro | 端侧；BYOK；符合资格时用平台私有云 | $0 | 一次性 $69（净得 $65.05） | 一次性，内含 BYOK 折扣 |
| Cloud | 托管，每月最多 160 万 token；之后转端侧 | ≤ $8.00 | $12/月（净得 $10.90） | 混合：订阅 + 额度 |

**私有档位改变了什么。** 在一台符合资格的 Mac 或 iPhone 上，云端级别的回答就包含在一次性的 Pro 里。它不能承诺「无限量」（平台会计量配额）、「端侧」（它是云，无论多么私密——像 M3 的各个模式那样，把它标为一个独立的隐私层级），也不能承诺永久（下载量达到 200 万时资格就结束）。保留 Cloud 档作为后备——而且它是 Windows 和 Linux 上唯一的云端选项，TinyCopilot 在这两个平台上也能运行（`course/03-content/m02-ondevice-app/tinycopilot/README.md`）。它的 $12 落在 Otter ~$8.33–16.99 的 Pro 区间之内（`ListenToMe/docs/competition-analysis.md`）：一条重复发生的推理成本线，被定了价。

**底线实例 2——一个 SignUpFlow 形态的 SaaS（类型 2）。** SignUpFlow 出厂时「没有托管服务、付费计划或生产部署」（`SignUpFlow/README.md`，Quick Start），它用贪心启发式算法而不是模型来排班。所以我们为一个假设的场景定价：为志愿者组织托管它，加上一个 LLM 功能，为每场活动起草排班公告，并在有人拒绝时提出换班建议。输入：

- **B1** 每个组织 40 名成员（3 名管理员，37 名志愿者）；**B2** 每月 12 场活动；**B3** 每月 250 封邮件（12 场活动 × 10 名志愿者 × 2，再加 10 封邀请）；**B4** 每场活动 2 次 LLM 调用，每次 2,500 个 token（2,000 输入，500 输出）——*假设*。费率是同样假设的 $0.005。
- **B5** 数据库 $25/月（Supabase Pro，05 §1，第三方）；在「SQLite（开发）/ PostgreSQL（生产）」的阶梯上，开发环境为 $0（`SignUpFlow/README.md`）。**B6** 托管 $20/月，即 05 §1 区间的上限——这是一个静态站点的估算，所以对 API 服务器来说只是下限。
- **B7** 邮件 $15/月，最多 40,000 封——*假设*，这是 SignUpFlow 已被取代的路线图中的数字（`SignUpFlow/docs/LAUNCH_ROADMAP.md`，已标记为历史文档）；请重新定价。
- **B8** 支付手续费 5% + $0.50（05 §2）。**B9** 构建时间 $666.67/月：320 小时 × $50 ÷ 24 个月——*假设*；320 小时是那份路线图自己的估算。

逐步算一遍。固定现金底线是 $25 + $20 + $15 = **$60/月**；加上构建时间是 **$726.67**。推理成本线是 12 × 2 × 2,500 ÷ 1,000 × $0.005 = **每个组织每月 $0.30**——之所以这么小，是因为调用次数随活动增长，而不是随成员增长。如果这个功能为每位志愿者、每场活动都运行一次，就是 $1.50：这就是你要设上限的那条线。邮件是阶梯式成本：40,000 ÷ 250 = **160 个组织**（免费和付费合计），之后套餐就要升级。用 SignUpFlow 自己 2025 年的计划中提出的价格——最多 50 名志愿者 $29，最多 200 名 $99（`SignUpFlow/docs/saas/STRIPE_INTEGRATION_PLAN.md`，一份 “Historical planning document”）——来检验，并把 AI 额度作为上限：

| 档位 | 席位 | AI 调用/月 | 价格 / 组织 / 月 | 手续费 | 达到上限时的 AI 成本 | 贡献 |
|---|---|---|---|---|---|---|
| Free | ≤ 10 | 无；完整排班 | $0 | — | $0 | 由固定成本套餐承担 |
| Starter | ≤ 50 | 50 | $29 | $1.95 | $0.63 | **$26.42** |
| Professional | ≤ 200 | 200 | $99 | $5.45 | $2.50 | **$91.05** |

**保本点：** $60 ÷ $26.42 → **3 个 Starter 组织**就能覆盖现金底线；$726.67 ÷ $26.42 = 27.5 → **28 个 Starter**（或 8 个 Professional）也能收回构建成本。推理成本最多约占 Starter 价格的 2%，所以决定保本点的是固定底线。按 Fellow 约 $7/用户/月的 Team 价格（`ListenToMe/docs/competition-analysis.md`），这个组织每月要为一个只有三名管理员在用的工具支付 $280：这就是按席位定价在惩罚志愿者增长。按席位区间定价，而不是按人头。

**第三个实例就是这门课。** 把 `course/04-sales/pricing-and-platforms.md` 读成这套方法在一个真实产品上的应用——就是这门课。阶梯是：$0 引流产品 → **$399** Studio 自学版 → **$1,490** Studio Live 直播班（创始价 **$990**）→ **$2,500–4,000** 团队档。不更便宜，是因为定价 ≥$950 的课程市场课程每次落地页访问多赚 50–100%，而 $500–1,500 的项目完课率为 53–68%，$97–197 的则是 18–25%——而完课就是这个产品本身。暂时不更贵，是因为还没有公开的推荐语：「在社会认同存在之前涨价，会颠倒信任的顺序」（全部出自 `pricing-and-platforms.md`）。而且创始折扣明确是一笔*交换*：$990（优惠 34%）「明确用来交换一段推荐语 + 一次 30 分钟的反馈访谈（在结账时达成约定）」。照搬的是记录格式，而不只是数字：底线、对标、区间、发布策略，以及一段从两个方向都经得起推敲的「为什么不更便宜 / 为什么不更贵」。

### 行动步骤

算出你的产品每月的成本底线——托管、API 密钥、摊销的开发时间——加上它的推理成本线和保本点，并写出你两句话的「为什么不更便宜」，引用 `course/00-research/02-course-market-research.md` 中的一个基准。把两者都发到社区；你会把它们粘贴进实验 M7 的工作表。

## M7.3 — 能带来转化的诚实营销（约 20 分钟）

### 目标

写出八个部分的销售页骨架；把主角的角色分配正确；解释为什么比你的受众更有怀疑精神反而能带来转化；并推导出一句定位一句话（positioning one-liner），它的每个分句都能对照你的表格被证伪。

### 讲解

```figure
kind: scene
alt: 一位买家阅读产品页面，按下购买，并收到一张收据。
scene: buyer-checkout.svg
caption: 买家是主角；页面是向导
```

**主角是买家。** 按研究的说法，StoryBrand 式的定位是：「学员是主角，你是向导」（`course/00-research/02-course-market-research.md` §E）。页面的每个部分都回答买家的问题——*这能让我到达目标吗？我能信任你吗？*——而不是你的问题。对技术受众来说，「真实交付的项目就是社会认同」（§E）：你从第 1 模块起一直在记录的仓库、演示、带日期的证据行和测试徽章，就是你的证明资产。用上它们。不要制造社会认同——本课程自己的规则是：「永远不要编造推荐语；在声称拥有社会认同之前，先交付测试版」（`course/04-sales/pricing-and-platforms.md`，诚实营销清单）。

**销售页结构。** 八个部分，来自研究中基于 32k+ 门课程整理出的模板——按这个思路重构页面，让一位创作者的转化率从 1% 提高到 8%（§E）：

1. **转变标题**——写成果（“Ship three production AI apps…”），而不是课程名称。
2. **适合谁——以及不适合谁。**
3. **问题与利害。**
4. **每个模块的成果**——把课程大纲表述为买家学完后能做什么。
5. **讲师证明**——相关性加上真实项目，100–150 词。
6. **推荐语**——按前/后/结果的形式书写（在它们存在时；见上文）。
7. **常见问题**——回答真实的异议：时间、水平、退款、「其他课程让我失望过」。
8. **透明定价，一个行动号召。**

篇幅随价格而定：$200 以下 800–1,200 词；$500+ 或面向冷流量时 2,000–3,000 词（§E）。第 8 模块会构建完整页面；今天你起草它的骨架，并真正写出其中三个部分。

**怀疑精神带来转化。** 本模块中最有力的证据来自 AI × QE。这个站点在它自己的幻灯片上公开写明「唯一的独立 RCT 结果是负面的」，并给每个规划数字盖上它标志性的限定语——「规划输入不是观察到的客户结果」（`course/00-research/03-ai-qe-deep-read.md` §1、§3）。观察到的效果，用深度解读的原话说：「一位高管在一家厂商的自家站点上读到『唯一的独立 RCT 结果是负面的』，就不再问『我凭什么相信你？』，而开始问『我们什么时候能开始？』」（§3）。机制是：**带来源的有限定的主张（qualified claim）是一种溢价信号。** 它们告诉买家，你对自己的审计比他们会做的还要严格——而一个读过你「这证明不了什么」一节的买家，他最廉价的异议（是否相信）已经被消除，只剩下真正的问题（开始日期）。这是把本课程的清单当作规则，而不是一种氛围：「任何销售材料上的每个数字都带来源」；「区分示意性的和实际观察到的」（`course/04-sales/pricing-and-platforms.md`，诚实营销清单第 1–2 项）。另一条路——把局限藏到购买之后——一接触就会失败：技术买家会在退款期内发现它们，而退款还算是好结局。

**定位一句话，是推导出来的，不是写出来的。** 第 3.3 模块从比较表出发，逐个分句推导出 ListenToMe 的定位；这个公式可以推广到每个产品：**形容词楔子（adjective-wedge）× 差异点 × 受众。** ListenToMe 的定位是：

> 「ListenToMe 是面向 macOS 的免费、开源、完全端侧运行的会议 copilot——自带模型，私密运行，并能适配任何对话。」（`ListenToMe/docs/competition-analysis.md:88`）

把每个分句追溯到一列，正是这一点让它可以被证伪，而不是一段氛围音乐：

| 分句 | 它来自哪一列 |
|---|---|
| 「免费」（free） | **价格**——这个领域从免费档一直到 $149.99/月；在 copilot 这个形态里，没有别的产品既免费又开源 |
| 「开源」（open-source） | **隐私 / AI 功能**——对手都是闭源、不公开的流水线；「代码公开可查」没有对应物 |
| 「完全端侧」（fully on-device） | **端侧？**——没有任何商业产品行；开源同类 Natively、Meetily 和 MacWhisper 也回答「是」 |
| 「自带模型」（bring your own model） | **多模型/BYO**——商业产品行写着「没有选择器」；四个开源同类回答「是」 |
| 「私密运行」（run it private） | **隐私**——自带本地 Ollama 意味着「没有音频需要离开本机」 |
| 「适配任何对话」（shape it to any conversation） | **聚焦**——对手只锁定一个垂直领域（tl;dv 做销售，Cluely 做面试，MacWhisper 做文件）；18 个用例预设服务许多场景 |

检验方法是删除：删掉一个分句，这句话就必须对某个具体的行变成假的。如果没有任何一行会察觉，这个分句就是装饰——删掉它。

### 行动步骤

为**你的**产品的销售页写出八个部分的骨架——全部八个部分的标题，每个一行——并为第 1 部分（转变标题）、第 2 部分（适合谁 / 不适合谁）和第 5 部分（讲师证明，引用一件你确实拥有的产物：一个仓库、一次测试运行、一行证据）写出*真正的草稿*。加上你会发布的那一句「这个产品不做什么」。把标题和诚实局限那一行发到社区。实验 M7 会把它夯实成一个包装页；第 8 模块会把骨架变成完整的销售页。

## 回顾

- **成本怎样重复发生，就怎样定价。** 重复发生的每用户云端算力 → 订阅（Granola、Otter）；端侧 → 一次性（MacWhisper）；免费开源 → 口碑漏斗、支持服务、Pro（Natively）。
- **应对重复成本的五种模式**——按席位、按用量、按结果、混合、BYOK 折扣——每一种都匹配一种成本形态，并惩罚另一种。
- **底线 = 固定成本项 + 一条推理成本线**，每个输入都有来源，或者写明是假设；保本点 = 底线 ÷ 贡献。TinyCopilot：每个云端用户每月 $8.00，每月 6 单 Pro。SaaS：每个组织 $0.30，现金层面 3 个 Starter 组织，算上构建时间是 28 个。
- **楔子必须在商业模式层面复制起来代价高昂。**
- **门控尚未证明的部分；永远不要门控核心**（`SignUpFlow/AGENTS.md`）。
- **类型 3 卖的是测量**，用一份收益实现登记表把每一项声称的节省挂到一条由财务负责的预算行上。
- **包装转变，而不是录像**；按分成、价格控制权和客户所有权来选择平台和渠道。
- **诚实带来转化，而定位一句话是从表格推导出来的**——每个分句都能对照一列被证伪。

## 讨论题

发出你的销售页草稿上*最*不愿意向一位怀疑派工程师辩护的那一个主张——然后写出它「这证明不了什么」的版本，以及你会附上的来源。你会发布这个有限定的版本吗？回复一位同伴：指出他们的定位语中哪个分句会被他们自己的比较表证伪，以及哪个分句经受住了删除测试。
